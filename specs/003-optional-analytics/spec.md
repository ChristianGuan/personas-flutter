# 003 — Analítica opcional (SDD previo a implementación)

## Inspección y límites
Flutter local 3.47.7, Dart 3.13.5; pubspec >=3.11, Android min28/compile36/target35, iOS16. Controlador ChangeNotifier, MethodChannel/EventChannel; Kotlin MediaStore/Photo Picker y Swift PhotoKit/PHPicker. Sin DB de uso, HTTP ni backend existentes. Los snapshots nativos de búsqueda son privados y ajenos a esta cola. Preservar selección de referencia/álbum, inferencia OpenCV/ONNX, revisión y funcionamiento sin internet. Convención specs/{spec,plan,tasks}. No aprovisionar servicios ni publicar credenciales.

## Requisitos y aceptación
Consentimiento explícito independiente del permiso de fotos, desactivado por defecto. Explicar finalidad (mejorar uso, estabilidad y resultados), métricas y límites; control visible en inicio. Sin consentimiento no crear UUID ni capturar/enviar eventos. Fallos de almacenamiento, red y programación no deben impedir buscar. Revocar bloquea capturas, vacía outbox transaccionalmente, cancela HTTP/trabajo y solicita borrado autenticado; si no hay internet conservar únicamente solicitud/credencial de borrado y reintentar, sin nuevos eventos. No reactivar hasta confirmar eliminación. Datos ya agregados sin identificadores no pueden vincularse para borrado.

Sólo enviar UUID aleatorios de instalación/evento, versión1, fecha UTC redondeada a hora, tipo y métricas permitidas. Nunca fotos/miniaturas, rostros, embeddings, claves de feedback, IDs/rutas/URI/nombres de álbum, EXIF, ubicación, identidad, identificadores de dispositivo ni trazas. No entrenar modelos. UUID de instalación generado después de aceptar, no es identidad; reportes dicen «por instalación». Credencial aleatoria de 256 bits en almacenamiento seguro, servidor sólo hash SHA256. No secretos administrativos en Flutter. Las solicitudes llevan Authorization; no logs de headers/cuerpos/IP persistidos.

## Eventos v1 / payload cerrado
- session_started: {} (cada entrada a primer plano, sólo tras aceptar).
- session_ended: {durationMs: entero 0..86400000}; ciclo de vida; cierres forzados pueden dejar inicio sin fin.
- search_started: {}.
- search_completed: {durationMs: 0..86400000, photoRange: 0|1-25|26-100|101-500|501+, matchRange: mismos rangos}. 0 sólo para conteo vacío de análisis parcial/resultados.
- search_cancelled: {durationMs, photoRange}.
- search_failed: {durationMs, errorCategory: permission|storage|processing|unknown}.
- results_rated: {stars: entero1..5}, una respuesta opcional por búsqueda completada; omitir no crea evento.
- results_reviewed: {confirmed: entero0..1000000, rejected: entero0..1000000}, totales explícitos enviados una vez al pulsar «Enviar revisión»; sin IDs individuales. Debe existir al menos una evaluación.
La app no registra completados restaurados como nuevas búsquedas. Si el proceso muere durante búsqueda no se inventa resultado ni duración; métricas pueden quedar incompletas. Duraciones limitadas a 24h.

## SQLite y dependencias
sqflite (SQLite nativo, operaciones fuera del hilo UI, transacciones/migración versionada), flutter_secure_storage (Keychain/almacenamiento cifrado de token), connectivity_plus (sólo señal para reintentar), workmanager (Android WorkManager/iOS BGTaskScheduler). dart:io HttpClient evita otro cliente HTTP; dart:math Random.secure genera UUID/token. sqflite_common_ffi sólo desarrollo permite probar persistencia real SQLite. Fijar versiones resueltas en lockfiles. No SDK de analítica de terceros.
Migración local v1: analytics_state singleton con enabled/installation_id/deletion_pending y reintentos de borrado, analytics_outbox(event_id PK, installation_id, type, schema_version, created_at, payload JSON cerrado, state pending, attempts, next_attempt). Transacciones para consentimiento, inserción, confirmación parcial y backoff. Máximo 5000 eventos /30d; descartar más antiguos por privacidad/capacidad incluso sin aceptación (excepción explícita a conservar hasta ACK). ACK elimina sólo IDs del lote aceptado. Tokens fuera de SQLite. Limpieza al abrir/sincronizar/insertar. No copiar snapshots de búsqueda a analítica.

## Sincronización
Persistir antes de enviar; lote50, respuesta API prueba conectividad real (no health probe adicional). Timeouts10s, cuerpo respuesta limitado, backoff exponencial 5s..6h con jitter; reintentos sin límite de intentos hasta expiración30d. API HTTPS excepto loopback en compilación debug. Endpoint vacío: cola offline sin envíos, nunca URL implícita. Disparadores: evento, conectividad, abrir/reanudar, temporizador mientras activa y tarea periódica15min best effort. iOS sistema decide ejecución; no prometer instantaneidad. Worker abre misma SQLite y comprueba consentimiento; borrado remoto con tombstone impide que envíos en vuelo resuciten datos. Cancelar HTTP del isolate UI al revocar; un worker ya en vuelo se neutraliza por borrado autenticado serializado en servidor. Credenciales de borrado retenidas hasta ACK para no perder derecho al borrar offline.

## Backend / contrato versionado
Node>=22, TypeScript, NestJS11 transporte, pg parametrizado, zod validación estricta, throttler límites por IP en memoria (sin almacenar IP en PostgreSQL/log); réplicas requieren limitador compartido/gateway antes de producción. domain sin Nest/pg, application casos de uso, infrastructure adaptador SQL/migraciones/config, presentation controllers/validación/auth, shared sólo configuración transversal necesaria.
- POST /v1/analytics/installations {installationId UUIDv4}, Authorization: Bearer token aleatorio64hex generado en cliente. Registro idempotente con mismo token, conflicto/revocada rechaza. No clave compartida embebida.
- POST /v1/analytics/events/batch {installationId, events:[{eventId,installationId,type,schemaVersion:1,createdAt,payload}]}, bearer propio. Máximo50/64KiB. Envelope inválido400; eventos individuales inválidos rechazados sin almacenarlos; transacción para aceptados, acceptedEventIds/rejectedIndices. EventId global único: aceptar duplicado sólo si contenido/instalación idénticos; conflicto rechazado. Fechas últimas30d, tolerancia futuro5min.
- DELETE /v1/analytics/installations/:id bearer propio. Borra eventos, marca tombstone30d; idempotente; id público insuficiente. Registro/envío/borrado toman bloqueo de fila; tombstone evita carrera.
- GET /v1/analytics/metrics?from=ISO&to=ISO, bearer ADMIN_TOKEN sólo entorno servidor, comparación segura; ventana [from,to), últimos30d y máximo31d. Instalaciones activas, sesiones/activa, búsquedas/activa, completadas/iniciadas, media/mediana duración, distribución/media estrellas (subjetiva), confirmadas/(confirmadas+rechazadas). Sin denominador devuelve null («sin datos»), nunca cero inventado.
- GET /v1/analytics/history protegido: agregados diarios sin IDs. Activos únicos de periodos históricos no son reconstruibles tras anonimización y no se suman como únicos.
Sin framework OpenAPI previo; contrato documentado en Backend/README, ejemplos y validadores compartidos backend. Errores HTTP genéricos sin cuerpo/trazas; límite60 peticiones/min y registro10/min. Límites no constituyen autenticidad de dispositivo; cliente público puede generar instalaciones. Producción exige HTTPS, gateway y límites globales, no atestación fingida.

## PostgreSQL y retención
Migraciones SQL versionadas aplicadas con script, advisory lock, transacción por migración. installation UUID PK + token_hash + deleted_at + last_seen. event_types catálogo; analytics_events UUID PK, instalación FK, tipo FK, schema1, timestamptz, payload jsonb limitado por app; índices instalación/fecha y tipo/fecha. Función/check SQL también bloquea payload arbitrario. daily_metrics fecha PK, contadores, sumas, distribución estrellas y duración agrupada por segundo sin UUID. Tarea hora agrupa eventos expirados por fecha y los elimina en una transacción; máximo30d configurable1..30; limpieza antes de servir reportes/ingestas. No permitir eliminación posterior de agregados anónimos. Programar mantenimiento al arrancar y cada hora; proceso caído requiere cron npm run retention para SLA estricto. Retención de últimos IDs deduplicados coincide con eventos: reenvíos expirados se rechazan por fecha.
